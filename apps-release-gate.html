01 · Executive summary

Apps are shipping fast. The standards are not keeping up.

The problem

Teams are building Databricks Apps quickly: internal tools, Genie-backed analytics front ends and agent chat interfaces on Mosaic AI. Today each app reaches a workspace through its own bundle with no common bar for security, identity, data access or AI controls. Review is manual, inconsistent and happens after the fact, if at all.

What we propose

  • A standards catalog written as policy-as-code: around 30 controls across security, identity, Unity Catalog, Genie, Agent Supervisor and operations, each with a severity per environment.
  • A release gate that runs inside the CI/CD pipeline between databricks bundle validate and databricks bundle deploy. A blocking failure stops the pipeline with a non-zero exit code.
  • Actionable reports: every finding names the file and line, the rule, why it matters and a concrete fix, posted to the pull request and stored for audit.
  • A compliance view in Unity Catalog so platform owners can see pass rates, waivers and repeat offenders across all apps.
POC outcomeThree representative apps (a CRUD tool, a Genie analytics app and an Agent Supervisor chat app) run through the gate in dev and prod targets, with at least one deliberate violation per category blocked and fixed end to end.
02 · Solution architecture

A gate in the pipeline, not a review after the fact

The gate is a small Python package and CLI (appgate) that ships as a reusable pipeline step for GitHub Actions or Azure DevOps. It reads the fully resolved bundle, inspects the app source, and optionally queries the target workspace to confirm that what the app references really exists and is configured safely.

Layer 1

Static source scan

Scans the app folder for hard-coded tokens and keys, unpinned or vulnerable dependencies (pip-audit, npm audit), unsafe patterns such as string-built SQL, and debug flags left on.

Layer 2

Bundle rules

Evaluates the resolved resources.apps block and app.yaml: declared resources, auth mode, permissions, environment variables, tags and per-target settings. Rules are YAML plus small Python checks.

Layer 3

Workspace verification

Read-only API calls using the pipeline's service principal: the Genie space exists and is shared correctly, serving endpoints have AI Gateway guardrails and inference logging, UC grants match the app's declared scope.

Design principles

Native to DABNo change to how teams write bundles; the gate reads databricks bundle validate -o json so variables and target overrides are already resolved.
Severity by targetThe same rule can warn in dev and block in prod, so developers are not slowed down while experimenting.
Waivers with an expiryA blocked rule can be waived only through a reviewed entry in appgate-waivers.yml with an owner, reason and end date.
AuditableEvery run writes its findings to a Delta table in Unity Catalog.

04 · Developer experience

A blocked release explains itself

When the gate stops a deploy, the developer sees the same report in the pipeline log and as a pull request comment. Each finding says where the problem is, why it matters and the exact change that fixes it.

$ appgate check --target prod
Apps Release Gate  bundle: sales-genie-app   target: prod   rules: 27

✖ BLOCK  SEC-001  Secret found in source
         app/config.py:14   API_KEY = "dapi3f…"
         Fix: move the value to secret scope sales-app, declare it as an
              app secret resource, and read it in app.yaml:
              env: [{ name: API_KEY, valueFrom: api-key }]

✖ BLOCK  GEN-002  Genie called with the app service principal
         app/genie_client.py:41   WorkspaceClient()  # app identity
         Fix: pass the user token from the request header so UC row
              filters apply to each user. See docs/genie-obo.md

✖ BLOCK  AGT-002  Endpoint sales-supervisor has no AI Gateway guardrails
         Fix: enable input and output safety and PII guardrails on
              the endpoint, then re-run the pipeline.

▲ WARN   OPS-003  compute_size LARGE without justification

────────────────────────────────────────────────────────
3 blocking · 1 warning · 23 passed      Deployment blocked (exit 1)

Rules are short and readable

Platform owners maintain standards as code. A typical rule is a few lines of YAML; anything that needs logic gets a small Python check registered under the same ID.

- id: GEN-001
  title: Genie space must be a declared app resource
  applies_to: apps
  severity: { dev: warn, test: block, prod: block }
  check:
    source_pattern: "space_id\\s*=\\s*['\"][0-9a-f]{32}"
    require_resource: genie_space
  fix: "Declare a genie_space resource and read its ID via valueFrom."

Pipeline wiring

One added step in the existing DAB pipeline. Deploy runs only if the gate exits 0; reports go out as SARIF, Markdown (PR comment) and a Delta table.

# one added step in the existing DAB pipeline
- run: databricks bundle validate -t $TARGET -o json > bundle.json
- run: appgate check --bundle bundle.json --target $TARGET \
         --report sarif,md,delta
- run: databricks bundle deploy -t $TARGET
  # runs only if appgate exits 0
